# Changelog

## v4.0.1 — November 6, 2026

ASADT4 (Mark IV) expands the toolset from three to eleven and adds a terminal execution path for every tool. Users upgrading from ASADT3 can keep the module-qualified launch commands. Python integrations need to update their imports. This entry compares the v4.0.1 source with [ASADT3 v2.1.0](https://github.com/Onetrak-Digital-Forensics/ASADT3/tree/v2.1.0).

### Eight new tool integrations

Each integration includes a desktop form, a terminal entry point, and a TOML file for defaults and report naming. The command links show the exact arguments ASADT passes to each installed program.

| Tool | What you can do | Implementation |
| --- | --- | --- |
| DNSRecon | Look up standard DNS records, service records, or certificate authority records. Choose DNS servers, TCP, a query timeout, and JSON, CSV, or XML output. The thread setting applies to standard and service-record lookups. | [Command builder](libasadt4/modules_main.py#L1013) · [Configuration](config/scantool/dnsrecon.toml) |
| WPScan | Scan a WordPress URL using passive, aggressive, or mixed detection. Set enumeration codes and a thread limit, and save a JSON report. | [Command builder](libasadt4/modules_main.py#L1054) · [Configuration](config/scantool/wpscan.toml) |
| assetfinder | Find subdomains or include related domains. ASADT captures standard output and replaces the destination report only after assetfinder exits successfully. | [Command builder](libasadt4/modules_main.py#L1061) · [Report writer](libasadt4/modules_main.py#L1174) · [Configuration](config/scantool/assetfinder.toml) |
| DIRB | Search a base URL with a built-in or custom wordlist. Set file extensions, recursion, and the delay between requests. | [Command builder](libasadt4/modules_main.py#L1065) · [Configuration](config/scantool/dirb.toml) |
| dnsmap | Discover names under a domain using a built-in or custom wordlist and a configurable maximum random delay. | [Command builder](libasadt4/modules_main.py#L1076) · [Configuration](config/scantool/dnsmap.toml) |
| MassDNS | Resolve a file of domain names against a separate resolver list. Select the DNS record type and concurrency limit, and save results in MassDNS’s simple text format. | [Command builder](libasadt4/modules_main.py#L1083) · [Configuration](config/scantool/massdns.toml) |
| DMitry | Run a domain or IP WHOIS lookup. Add subdomain discovery, email discovery, or TCP port scanning to the same report. | [Command builder](libasadt4/modules_main.py#L1088) · [Configuration](config/scantool/dmitry.toml) |
| SpiderFoot CLI | Connect to a running SpiderFoot server, run a command file or continue interactively, and save the session output. The form accepts a username and password file and can disable local command history. | [Command builder](libasadt4/modules_main.py#L1095) · [Configuration](config/scantool/spiderfoot-cli.toml) |

### Changes to the three existing tools

- **Nmap scan controls.** The shipped configuration now skips the NSE database rebuild and sets a three-minute host timeout. The new timeout and maximum packet rate apply to both the main scan and the optional traceroute. Traceroute also honors IPv6. A failure in the database rebuild or traceroute stops the run and returns that command’s status. [Shipped defaults](config/scantool/nmap.toml) · [Execution order](libasadt4/modules_main.py#L915) · [Limit handling](libasadt4/modules_main.py#L948)
- **Nmap argument fixes.** Selecting timing preset zero now passes `-T0`. An NSE script arguments file works whenever script scanning is enabled, independently of script traffic tracing. The GUI displays names such as **TCP Connect Scan** while accepting the existing TOML value `Connect() Scan`. [Scan method mapping](libasadt4/gui_models.py#L19) · [Command builder](libasadt4/modules_main.py#L986) · [Argument regression tests](tests/test_regressions.py#L654)
- **Nikto.** The user-agent field now passes the supplied value, and the legacy string `'False'` correctly disables the tool. Automatic SSL detection clears both explicit SSL overrides. The form adds an application root path and a per-host time limit alongside request timeout and pause. The shipped `current` profile supports `-nocookies`. Configurations missing the profile key use the `legacy` profile for versions with `-usecookies`. [Configuration and profile selection](config/scantool/nikto.toml) · [Command builder](libasadt4/modules_main.py#L1027) · [SSL regression test](tests/test_regressions.py#L266)
- **MSFPC.** Single, loop, and batch modes now validate only the settings each mode uses. Switching modes preserves inactive selections. Loop takes the entered address and optional port in the correct positions. Batch also uses the chosen console. MSFPC runs in the selected output directory while the launching process keeps its working directory. [Mode controls](libasadt4/displayboxhandler.py#L450) · [Combination checks](libasadt4/modules_main.py#L397) · [Execution and argument order](libasadt4/modules_main.py#L1125)

### Desktop forms and terminal commands

- **Desktop workflow.** PySide6 replaces PySimpleGUI. Forms group options into scrollable sections, use title-case field labels, and provide hover help with examples. Users can browse for paths, adjust supported numeric settings with a slider or by typing, and preview reports before running. On Wayland, file pickers and confirmations use Qt dialogs. [Form construction](libasadt4/displayboxhandler.py#L69) · [Field controls](libasadt4/displayboxhandler.py#L339) · [Qt initialization](libasadt4/displayboxhandler.py#L762)
- **Run-specific and saved settings.** **Runtime Config** edits a private copy of the selected tool’s configuration. The preview and command use that same copy. **Edit TOML in CnfEdit** opens the saved file for persistent changes. The new `python asadt.py cnfedit` command lists configuration files before parsing them, so users can repair malformed TOML. The editor tries nano, Vim, and vi, with a Notepad fallback for writable edits on Windows, and preserves file permissions by default. [Runtime settings](libasadt4/displayboxhandler.py#L212) · [Configuration picker](asadt.py#L82) · [Editor launcher](libasadt4/mainprog.py#L127)
- **Discovery and direct execution.** `python asadt.py run` lists every tool, and `run scantool` lists one module. Both `run nmap` and `run scantool nmap` open the Nmap form. Supply `--target` to execute from the terminal. Use `--ports` and `--script` for an Nmap scan, `--resolvers` for a MassDNS resolver file, and `--output-dir` to choose the destination. Both interfaces start from the same saved defaults. [Tool resolution](asadt.py#L105) · [Terminal option mapping](asadt.py#L201) · [Shared defaults](libasadt4/tool_config.py#L184)
- **Startup and permissions.** The CLI locates configuration relative to `asadt.py`, so launching from another directory works. Help, version, and terminal commands load without opening Qt. The global root check has been removed. Nmap now identifies the selected options that need elevated permissions and prompts before proceeding. Form edits that introduce another privilege requirement trigger a new check. [Configuration location](asadt.py#L58) · [Run dispatch](asadt.py#L250) · [Privilege checks](libasadt4/privileges.py#L36)

### Input validation, execution, and reports

- **Targets and scripts.** ArgVerify checks Nmap CIDR targets, IPv4 octet ranges, and protocol-qualified port lists such as `T:80,443,U:53`. It resolves hostnames in the selected IP family. It also checks NSE script expressions against the local script catalog or a supplied path. With verification and NSE scanning enabled, a blank selection uses `not intrusive`. [Target and port checks](libasadt4/modules_main.py#L253) · [NSE selector checks](libasadt4/modules_main.py#L687) · [Verification defaults](libasadt4/modules_main.py#L771)
- **Input files and corrections.** MassDNS domain and resolver lists, Nikto host files, and custom DIRB and dnsmap wordlists are checked before execution. A malformed entry identifies its field and line. The GUI returns focus to the rejected field and retains the other entries. An interactive terminal offers a retry. Noninteractive verification failures return status `3`. The GUI verification switch and terminal `--no-argverify` apply to one run. Output-path and overwrite checks still apply. [File validation](libasadt4/modules_main.py#L526) · [GUI correction](libasadt4/displayboxhandler.py#L565) · [Terminal retry](asadt.py#L146)
- **Native execution and exit status.** ASADT passes an argument list directly to each executable. Paths containing spaces and values containing shell metacharacters reach the tool as individual arguments. The launcher returns the native exit status. A missing executable or launch I/O error returns `127`, so scripts can distinguish a launch failure from a successful scan. [Process launcher](libasadt4/modules_main.py#L1192) · [Argument and exit-status tests](tests/test_regressions.py#L878)
- **Report handling.** The GUI previews destination paths, and both interfaces check writability and ask before creating directories or overwriting reports. For Nmap `-oA`, the check covers `.nmap`, `.xml`, and `.gnmap`. Nmap and Nikto require a plain report filename. Nmap also rejects `%` in the filename or output directory because it expands those paths at execution. Existing report symlinks pointing outside the selected directory are rejected. MSFPC chooses its own filenames, so a nonempty directory triggers confirmation. File-based inputs for the new reconnaissance tools are also checked against the destination to prevent overwriting an input file. [Path and collision checks](libasadt4/output_paths.py#L46) · [Input-file protection](libasadt4/output_paths.py#L94) · [GUI preview](libasadt4/displayboxhandler.py#L519)
- **Diagnostics.** `--debugger` reports the Python interpreter, virtual environment, configuration path, permissions, and selected runner. The trace follows submitted fields through verification and records the native argument list, working directory, elapsed time, and exit status. Designated credential, proxy, and key-file fields are redacted in the form and command traces. [CLI diagnostics](asadt.py#L250) · [Form trace](libasadt4/displayboxhandler.py#L501) · [Command trace](libasadt4/modules_main.py#L1192)

### Installation, updates, and migration

- **Python environment.** Use Python 3.10 or newer and install the current requirements in a fresh virtual environment. Dependencies now include PySide6 and Requests, plus `tomli` for Python 3.10. The README includes Kali Linux and Parrot OS setup instructions, a localhost scan, and matching Nmap and Nikto screenshots. [Python dependencies](requirements.txt) · [Installation and first scan](README.md#install-on-kali-linux-or-parrot-os)
- **External tool installation.** The existing `sudo .venv/bin/python asadt.py update --apt-dep-update` command now reads and validates `[APT_DEP].dependency_list` from `config/scriptinfo.toml`. It checks for root, refreshes the APT index, and runs the install step only if the refresh succeeds. APT failures propagate to the caller. The package list includes `spiderfoot` for the `spiderfoot-cli` executable. [Package list](config/scriptinfo.toml) · [APT installer](libasadt4/mainprog.py#L336)
- **Release downloads.** The release check and tag archive URLs now point to ASADT4. Metadata and archive requests have a 30-second timeout. The release check parses metadata in memory. Archive downloads are staged beside the destination and replace it after a successful write. The updater still compares version strings for inequality, so a different remote identifier can trigger a download prompt even if it names an older version. [Release endpoints](config/scriptinfo.toml) · [Download handling](libasadt4/mainprog.py#L220) · [Version comparison](libasadt4/mainprog.py#L293)
- **Python integrations and TOML compatibility.** Change `libasadt3` imports and test patch targets to `libasadt4`. The form service retains `DISPLAY_UI_MODEL()` and its integer-keyed values. The runners copy submitted arguments before verification and fill missing newer fields for older callers. Tool switches accept native TOML booleans and legacy strings such as `'True'` and `'False'`. Invalid defaults and report settings identify the configuration key to correct. [Form service](libasadt4/displayboxhandler.py#L789) · [Legacy argument defaults](libasadt4/modules_main.py#L82) · [Configuration validation](libasadt4/tool_config.py#L212)

### Tests and repository changes

- Added a regression suite covering form and configuration parity for all eleven tools, terminal dispatch, native argument construction, permission prompts, overwrite decisions, and failure handling. Run `python -m unittest discover -s tests -v` from the checkout. Qt tests use an offscreen display, and native tool executions are mocked. Update tests use a controlled metadata response and check that existing local files survive both valid and malformed responses. [Tool coverage](tests/test_regressions.py#L256) · [Overwrite tests](tests/test_regressions.py#L509) · [CLI startup and dispatch](tests/test_regressions.py#L1148)
- Added a contributor reference for the CLI, form models, validators, runners, and tests. The bug report template now asks for the ASADT4 version. Git normalizes project text to LF, treats PNGs as binary, and ignores local environments, caches, downloaded archives, and the default Nmap report in the repository root.
